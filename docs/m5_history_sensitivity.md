# Дополнительная проверка длины истории

План добавлен после основного исследовательского теста r4.2/r5.2 и до test r6.2.
Он не меняет основной M5, его порог, comparator и критерий успеха. Причина:
естественные test-когорты почти не содержат короткой истории n_eff<30; пустая
группа не позволяет измерить качество при недостатке пользовательских данных.

Фиксированный набор максимальных объёмов личной истории: 10,30,60,90,120 user-days.
Для каждой ёмкости обрезается исходная история и ограничивается дальнейшее хранение;
глобальная/ролевая calibration-опоры используют полный прежний calibration.
Остальные формулы, параметры, даты и детектор не меняются. Сдвиг роли и порог
калибруются заново только на тех же guard/threshold-validation, затем фиксируются.
Пять seeds на выпуск. Никакой выбор нового победителя из ёмкостей не допускается.

Результаты — описательная sensitivity-проверка, без включения в первичную семью
статистических тестов. На рисунке показываются среднее и диапазон пяти seeds,
который не называется доверительным интервалом. Основная статистика относится
исключительно к неизменённому M5 с ёмкостью 120.

Для воспроизводимости используется AST-производная model.py: только числовые
константы 120/119 заменяются на capacity/capacity-1. Ёмкости >=10 сохраняют безопасное
хранение 7-дневного AB-буфера. Сгенерированный код и его SHA256 сохраняются отдельно.
Исходный model.py и frozen_plan не изменяются. При capacity=120 результаты должны
побитно/с численной точностью совпасть с основным M5 — это обязательная проверка.
