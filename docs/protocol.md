# Предварительный протокол исследования

Дата фиксации: 2026-11-02 (Europe/Moscow). Документ создан до обучения и просмотра тестовых оценок.

## Цель и ограничения

Проверить M4 из task.md относительно M0–M3 на CERT r4.2. Отрицательный и неопределённый
результаты допустимы. CERT — синтетический набор, выводы не означают проверку на реальных
корпоративных данных. M4 — сглаженная смесь эмпирических хвостовых вероятностей; строгие
conformal-гарантии для этой смеси не утверждаются.

## Данные и единица наблюдения

Основной источник — официальный архив CERT r4.2 и answers.tar.bz2 из Figshare/CMU.
Первый основной эксперимент использует logon, device, file, email; HTTP исключён для
снижения вычислительной нагрузки. Единица — активный user-day, оценка в конце календарного дня.
Входные журналы дедуплицируются по идентификатору события; коллизии требуют остановки.
Уточнение по официальной errata r4.2, прочитанной до агрегации/обучения: идентификатор
уникален только внутри журнала. Разметка сопоставляется по паре `(event_type,id)`.
В r4.2 каждая строка file.csv означает копирование на съёмный носитель;
`file_events` не трактуется как счётчик любых файловых операций.
Метка 1 означает наличие хотя бы одного относящегося к инциденту события из официального
ключа r4.2 в этот день. Аудит до обучения выявил обычные ответы руководителей в сценарии 3:
они исключаются; события входа/выхода и массового письма под украденной учётной записью
на следующий после переноса keylogger день включаются под наблюдаемой учётной записью.
Сохраняются и учётная запись, и фактический insider из имени incident-файла.
Ключи включают подготовительную активность, поэтому метки точнее называть
«user-day с подтверждёнными incident-observables», а не доказательством злого умысла каждого события.
Широкие интервалы сценариев не заменяют событийную разметку. Метки могут опираться и на HTTP,
даже если HTTP-признаки исключены: потеря наблюдаемости сценариев будет указана отдельно.
Роль — последний LDAP-снимок с датой не позже дня наблюдения. Недоступная роль получает
явное значение UNKNOWN, без переноса будущего снимка назад.

Zenodo 19435851 используется только для аудита и предварительного прототипирования:
публикационная пригодность не предполагается без проверки исходного кода агрегации,
временных окон, нормировки и точности меток. Психометрические и NLP-признаки не используются.

## Признаки

Счётчики входов/выходов, USB-подключений, файловых операций, писем, внешних адресатов,
уникальных рабочих станций и суммарных событий. Действия вне фиксированного окна
08:00–18:00 по времени журнала (не индивидуально выученное рабочее время); отдельно выходные.
Фиксированное окно — операционное определение, а не доказательство нетипичности для сотрудника.
Сессии не восстанавливаются без отдельной проверки. Идентификаторы, даты, роль и метки не
подаются в IsolationForest. Обработка пропусков и нормировка обучаются на train.

## Временные блоки

Основной протокол — 50/20/15/15 процентов глобального календарного диапазона, а не числа строк.
Границы вычисляются один раз, до обучения. Сохраняются размеры и положительные user-day/пользователи.
Если в закрытом тесте <20 положительных дней или <5 положительных пользователей,
результат recall помечается как недостаточно обеспеченный данными. Это рабочий критерий
предосторожности, не формальный power-анализ.

Дополнительный временной протокол, если основной тест неинформативен: три заранее заданных
расширяющихся окна с долями train/calibration/validation/test [30/15/10/15], [40/15/10/15],
[50/15/10/15] от всего календарного диапазона, остаток после соответствующего теста исключается.
Каждое окно оценивается отдельно; перекрывающиеся тесты не объединяются в независимые наблюдения.
Основной результат не заменяется наиболее удачным окном.

## Модели и история

На seed один общий IsolationForest: 200 деревьев, max_samples=min(2048,n_train), n_jobs=-1.
Seeds: 42, 43, 44, 45, 46. Обучение без удаления положительных train-строк по ответам:
это несупервизируемый детектор на потенциально загрязнённом фоне; загрязнение измеряется.
Все M0–M4 используют одни и те же scores.

История калибровки заморожена после calibration-блока для validation и test;
ни validation, ни test не пополняют профили. Это исключает включение оцениваемого дня.
Индивидуальная история относится к пользователю, ролевая — к роли на день события.
M1 fallback global при n_role<30; M2 fallback global при n_user<5.
M3 — 0.5*p_user+0.5*p_role; каждый отсутствующий профиль заменяется global.
M4 использует все доступные профили с k_user=30, k_role=200 и нулевым весом отсутствующего.
Для M1–M4 score=-log(p), больше — аномальнее. Равные scores имеют равные пороги;
для top-K порядок связок определяется SHA256(user,date), одинаково для методов.

## Оценка

Ретроспективные Precision@K/Recall@K при ceil(0.5%,1%,2% * n_test).
Проспективный порог: верхний эмпирический 99%-квантиль validation, тревога score>threshold.
Из-за связок фактическая доля может быть меньше 1%; сохраняется вместе с порогом.
Отдельный порог FPR<=1% выбирается только по отрицательным validation-дням;
нарушение ограничения на тесте явно отражается в результатах.
PR-AUC определяется как average precision; ROC-AUC не определяется при одном классе.
FPR роли считается на отрицательных днях роли; основной max-role FPR — по всем ролям
с отрицательными днями, дополнительно показывается вариант n_negative>=100.

Ablation: без user; без role; постоянные веса; исходные зависимые от n веса;
сетка k_user={10,30,90}, k_role={50,200,800}. Сетка — анализ чувствительности, не выбор по тесту.
Основной M4 всегда 30/200. Короткая история: 0, 1–4, 5–14, 15–29, >=30 calibration-дней.

Уточнение до обучения и открытия тестовых scores: если естественная calibration-история
почти всех работников длинная, дополнительно применяется заранее заданное усечение
персонального профиля до последних {1,3,5,10,20,30,60} calibration-дней. Global и role
остаются полными, сравниваются M2/M3/M4 с отдельным validation-порогом для каждого
усечения. Это контролируемый стресс-тест короткой истории, а не естественная новая когорта.
Он не заменяет основной результат и не используется для выбора k.

## Статистика и критерий

95% CI: парный кластерный bootstrap по пользователям (1000 выборок для основных сравнений),
одни и те же выбранные пользователи у методов. Повторы seed отражают алгоритмическую
нестабильность и не считаются независимыми новыми пользователями.
Основной bootstrap — среднее метрик по пяти seeds внутри каждой выборки пользователей.
Заранее заданные сравнения M4−M0 и M4−M3; поправка Holm по основной семье проверок.
Критерий практической значимости: max-role FPR снижается >=20% относительно M0 при
потере recall<=0.02 либо значимый прирост Recall@1% относительно M0.
Для утверждения о пользе иерархических весов требуется также выигрыш относительно M3.
Нулевая положительная поддержка и bootstrap-выборки без положительных пользователей
обязательно отражаются; отсутствие доказательств не приравнивается к доказанному равенству.
До открытия тестовых модельных оценок оцениваются минимально различимые изменения recall
по числу положительных пользователей и дней; кластерная зависимость ограничивает выводы.
