# ЗАДАНИЕ 

## 1. Роль и цель

Ты — исследователь и инженер машинного обучения в области информационной безопасности, специализирующийся на UEBA, обнаружении аномалий и воспроизводимых вычислительных экспериментах.

**Тема статьи:**

«Метод иерархической контекстной калибровки оценок аномальности для снижения ложноположительных срабатываний в системах анализа поведения пользователей».

**Цель:** разработать, реализовать и экспериментально проверить метод иерархической контекстной калибровки оценок аномальности, учитывающий глобальную, ролевую и индивидуальную статистику поведения.

Исследование должно ответить на два вопроса:

1. Какими измеримыми недостатками обладают глобальная, групповая и индивидуальная калибровки оценок аномальности?
2. Улучшает ли предложенная иерархическая калибровка обнаружение внутренних угроз и распределение ложных тревог между группами пользователей по сравнению с существующими подходами?

Не используй GAN, генеративные нейросети или LLM в качестве экспериментальных моделей.

**Критически важно:** не подгоняй результаты под гипотезу. Если предложенный метод проигрывает существующим решениям, зафиксируй это и объясни причины. Не создавай вымышленные экспериментальные значения, научные публикации или графики.

## 2. Исследовательская гипотеза

Н0: иерархическая контекстная калибровка не обеспечивает улучшения операционных показателей UEBA по сравнению с глобальной, ролевой и индивидуальной калибровками.

Н1: иерархическая контекстная калибровка с учётом количества исторических наблюдений улучшает качество обнаружения при фиксированном бюджете тревог и/или снижает концентрацию ложноположительных срабатываний в отдельных ролевых группах без существенного ухудшения обнаружения.

Дополнительная гипотеза: при короткой индивидуальной истории предлагаемое взвешивание статистик обеспечивает более устойчивые результаты, чем исключительно персональная калибровка.

## 7. Реализация базового детектора

Используй `IsolationForest` из `scikit-learn`.

Исходные параметры:

- `n_estimators=200`;
- `max_samples=min(2048, n_train)`;
- `random_state=42`;
- `n_jobs=-1`.

Допускается корректировка параметров на валидации при одинаковом бюджете настройки для сравниваемых методов.

Нормализация и обработка пропусков должны обучаться только на train.

Приведи выдаваемый алгоритмом показатель к соглашению: **большее значение означает более аномальное наблюдение**.

Обучи один общий детектор и сохрани его оценки для всех сравнений.

## 8. Реализация пяти методов

**M0 — глобальная оценка.**

Используй исходный score Isolation Forest и глобальный порог.

**M1 — ролевая калибровка.**

Преобразуй score в эмпирическую верхнехвостовую вероятность внутри ролевой группы.

При недостаточном числе наблюдений предусмотрительно используй глобальную статистику и зафиксируй правило.

**M2 — индивидуальная калибровка.**

Аналогично используй исторические оценки конкретного пользователя. При отсутствии достаточной истории переходи к глобальной статистике.

**M3 — простая комбинация.**

Сравни M4 с простым равновесным объединением индивидуальной и ролевой статистики. Для отсутствующих профилей используй документированный fallback.

**M4 — предлагаемый метод.**

Реализуй трёхуровневую иерархическую калибровку.

Для каждого исходного score `s` вычисляй:

`p_global(s)` — долю калибровочных оценок не меньше `s` среди всех наблюдений;

`p_role(s)` — аналогичную долю внутри роли;

`p_user(s)` — аналогичную долю в истории пользователя.

Применяй сглаженную эмпирическую формулу:

`p(s) = (1 + number_of_scores_greater_or_equal_s) / (n + 1)`

Затем:

`w_user = n_user / (n_user + k_user)`

`w_role = n_role / (n_role + k_role)`

`p_hier = w_user*p_user + (1-w_user)*(w_role*p_role + (1-w_role)*p_global)`

`score_hier = -log(p_hier)`

Начальные значения:

- `k_user=30`;
- `k_role=200`.

Это стартовые параметры, а не заранее доказанные оптимумы. Дополнительно проведи анализ чувствительности по нескольким значениям.

При отсутствии пользовательской или ролевой истории соответствующие веса должны быть нулевыми.

Реализуй функции в отдельных модулях с тестами.

Не заявляй, что полученная смесь автоматически обладает строгими теоретическими гарантиями conformal prediction.

## 10. Эксперимент № 2 — проверка нового метода

Сравни M0, M1, M2, M3 и M4.

Используй два отдельных протокола.

### A. Ранжирование при фиксированном бюджете

Рассчитай `Precision@K` и `Recall@K` при K, равном 0,5%, 1% и 2% общего числа тестовых пользовательских дней.

Это ретроспективная оценка качества ранжирования; не представляй её как реальное онлайн-управление бюджетом тревог.

### B. Проспективный порог

На валидации зафиксируй для каждого метода порог, соответствующий целевой доле тревог 1%.

Примени порог к закрытому тесту, не перенастраивая его.

Измерь фактические:

- FPR;
- Recall;
- Precision;
- F1;
- PR-AUC;
- ROC-AUC;
- ложные тревоги на 1000 пользовательских дней;
- FPR по ролям и максимальный ролевой FPR.

Дополнительно исследуй sensitivity при условии FPR не выше 1%, честно указав, если выбранный на валидации порог нарушил эту границу на тесте.

Особое внимание удели сравнению M4 с M3. Если выигрыш относительно простой комбинации отсутствует, преимущество иерархического взвешивания не доказано.

Для M4 проверь:

- с постоянными весами;

Не выбирай лучший вариант задним числом по тестовым результатам.

## 12. Статистический анализ

Выполни не менее пяти повторов для стохастических этапов.

Используй:

- 95%-е доверительные интервалы;
- bootstrap с кластеризацией по пользователям;
- парное сравнение методов по одинаковым тестовым наблюдениям;
- поправку на множественные сравнения при необходимости;
- анализ различий на уровне отдельных ролевых групп.

Не трактуй соседние пользовательские дни одного человека как независимые наблюдения.

Предварительно оцени размер эффекта.

Предлагаемый критерий практической значимости для пилота: снижение максимального ролевого FPR минимум на 20% относительно M0 при ухудшении recall не более чем на 2 процентных пункта, либо самостоятельный значимый прирост recall при одинаковом бюджете тревог. Это предварительные критерии, их нельзя менять после просмотра закрытого теста.

Если числа положительных наблюдений недостаточно для такого вывода, явно укажи недостаточную статистическую мощность.
