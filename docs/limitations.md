# Журнал ограничений и технических исправлений

2026-11-02, до обучения:

- Обычный запуск PowerShell возвращает Windows 740; разрешённые чтения и расчёты
  выполняются через запуск с повышением. Изменений системной политики не выполнялось.
- Windows tar не смог открыть bz2 из-за отсутствия внешнего bzip2; используется
  стандартный Python tarfile/bz2, с запретом извлечения ссылок и traversal-путей.
- Архив CERT содержит составной bzip2-поток; внутренний tarfile r|bz2 останавливался
  на первом потоке. Исправлено использованием BZ2File поверх последовательного tar.
- В проверке LDAP обнаружено несовпадение datetime64[s]/datetime64[ns]; ключи join
  приведены к единой ns-точности, тест с будущим снимком успешно проходит.
- Основные признаки пока ограничены logon/device/file/email; HTTP не используется.
  Ключи с HTTP сохраняются для меток и оценки потери наблюдаемости.
- Формула M4 является эмпирической смесью; конечновыборочные conformal-гарантии
  и гарантированный онлайн-бюджет тревог для неё не доказаны.
- Ключи incident-observables включают подготовительные действия и обычную переписку.
  20 ответов руководителей исключены; 30 событий под украденными учётными записями
  сохранены. Дни риска из insiders.csv не растягиваются на всю историю пользователя.
- CERT синтетический: внешняя валидность для реальных компаний не установлена.
- README r4.2 предупреждает: ID уникальны только внутри журнала. Ключи сопоставляются
  по `(event_type,id)`. `file.csv` содержит копирование на съёмные носители, а не
  полный аудит операций с файлами. README также содержит устаревшую фразу о двух
  угрозах; число сценариев/участников определяется фактическими official answer keys.
- Поддержка положительных примеров, доверительные интервалы и пригодность гипотезы
  определяются фактическими расчётами; на этапе создания документа результатов нет.

Zenodo 19435851: оба parquet загружены и MD5 проверены. По 330452 строк;
в обоих файлах отсутствует целевая метка. В engineered-матрице присутствуют
z-score, rolling- и агрегированные login-hour-признаки без кода происхождения.
Файл содержит пропуски role/department/functional_unit. Независимо подтвердить
причинность нормировок и временных окон нельзя. Матрицы **исключены из основного
эксперимента**, наличие столбцов само по себе не доказывает фактическую утечку.

Дополнительная численная проверка Zenodo: для всех пяти `*_z_user` столбцов
точно воспроизведена формула `(x - mean_user_all_dates) / std_user_all_dates(ddof=1)`
с нулевым заполнением постоянных профилей. Максимальная абсолютная ошибка 0.0,
доля совпадений 100% на 330452 строках для каждого столбца. Следовательно, эти
готовые признаки нельзя принимать за причинные в хронологическом эксперименте:
они эквивалентны нормировке всей, включая будущую, истории. Исходный код
производителя по-прежнему не получен. Проверка: `python tools/audit_zenodo.py`,
результат `data/metadata/zenodo_audit.json`.

После получения модельных scores, на старте bootstrap выявлено переполнение int16
в pandas categorical-кодах при вычислении user*42+role для 868 тестовых аккаунтов.
Исправлено приведением к int64 **до** умножения; добавлена регрессионная проверка
индексов >32767. Исправление относится к адресации кластеров; модели, пороги,
параметры M4 и тестовые наблюдения не выбирались заново.

Итоговая поддержка основного теста: 45460 дней, 65 положительных дней у 9 аккаунтов;
61 положительный день относится к сценарию 2, по сценариям 1 и 3 поддержка крайне мала.
Все тестовые пользователи присутствуют в train; естественный cold-start тест
невозможен. У всех тестовых дней >=30 calibration-дней истории, поэтому вывод
о короткой истории опирается только на контролируемое усечение, не на новую когорту.
Одна из 1000 bootstrap-выборок не содержит положительных дней: для recall/AP/AUC
использованы оставшиеся 999 и соответствующий счётчик явно сохранён.
Отдельные bootstrap-выборки не содержат отрицательных дней некоторых малых ролей;
их role-FPR помечен неопределённым, а не нулём (возможен RuntimeWarning при nanmean).
