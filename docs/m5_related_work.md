# Ближайшие научные аналоги M5

Проверено по первичным источникам 2026-11-02. Поиск: adaptive conformal inference,
group-conditional calibration, hierarchical shrinkage, streaming EVT, conformal
martingales, multivalid calibration. Отсутствие найденного точного совпадения не
доказывает приоритет. Ни один из перечисленных результатов не даёт автоматически
FPR-гарантию нашему объединению зависимых user-days с экстраполированными хвостами.

| Источник | Близкий механизм | Отличие и ограничение M5 |
| --- | --- | --- |
| [Bowie, Larijani & Qureshi, Computers 2026, CRD](https://researchonline.gcu.ac.uk/en/publications/counterfactual-routine-deviation-personalised-behavioural-modelli/) | Персональные поведенческие нормы, peer-relative отклонения и комбинация компонентов для insider detection | По проверенной аннотации CRD использует r6.2, более широкие routine/content/destination/organisation признаки и insider-risk windows. M5 калибрует один IF-score на 17 сопоставимых признаках и официально отмеченных account-days. Чужие AUROC/Precision нельзя напрямую сравнивать с нашим пороговым Recall. Сам принцип персонального/peer контекста уже известен. |
| [Kantchelian et al., USENIX Security 2026, Facade](https://www.usenix.org/conference/usenixsecurity26/presentation/kantchelian) | Контекст пользователя и ресурса, обнаружение одиночных подозрительных событий, self-supervised обучение | Facade обучает многомодальное контекстное представление на корпоративных журналах; M5 — надстройка над одномерным score общего IF, без нового representation learning. Данные/единицы наблюдения различаются, поэтому заявленный чужой FPR не является экспериментальным baseline нашего CERT-протокола. |
| [Gibbs & Candès, NeurIPS 2021, Adaptive Conformal Inference](https://papers.neurips.cc/paper_files/paper/2021/hash/0d441de75945e5acbc865406fc9a2559-Abstract.html) | Онлайн-адаптация к сдвигу распределения через обратную связь о покрытии | M5 не получает истинные test-метки и не изменяет порог по test-ошибкам. Он обновляет личную историю scores. Гарантии ACI к нему неприменимы. |
| [Gibbs & Candès, Conformal Inference for Online Prediction with Arbitrary Distribution Shifts](https://arxiv.org/abs/2208.08401) | Адаптация шага при разных формах дрейфа | У M5 фиксированные константы и эвристический коэффициент устойчивости. Он не доказывает их regret-оптимальность. |
| [Siffer et al., KDD 2017, SPOT/DSPOT](https://www.amossys.fr/wp-content/uploads/anomaly-detection-with-evt-1.pdf) | Потоковая оценка хвоста и адаптация к дрейфу для обнаружения аномалий | M5 использует простую экспоненциальную экстраполяцию, а не оценённый обобщённый Pareto SPOT. Он сочетает user/role/global и фиксирует конечный порог на validation. |
| [Martinez Gil et al., UAI 2024](https://proceedings.mlr.press/v244/martinez-gil24a.html) | Однородность групп nonconformity scores и group-conditional calibration | M5 использует наблюдаемые профессиональные роли LDAP; не обучает разбиение пространства признаков. Ролевой guard — эмпирический сдвиг хвоста, без новой гарантии группового покрытия. |
| [Bukkapatnam, HCC-CP, JSM 2026](https://ww2.amstat.org/meetings/jsm/2026/onlineprogram/abstract.cfm?sid=8751&tid=9087) | Иерархическое объединение conformity scores с весами по объёму сообщества | Уже известен близкий принцип size-dependent shrinkage. Доступен тезис постера; он не равнозначен подробной рецензируемой статье. У M5 дополнительно причинная личная история, оценка её устойчивости, накопление и одиночный путь. Сам shrinkage не является новой идеей. |
| [Hennhöfer & Preisach, 2026](https://arxiv.org/abs/2603.23205) | Эффективный объём истории, потеря хвостового разрешения и непрерывная калибровка | Непрерывность персонального хвоста и зависимость от effective sample size уже исследованы. M5 применяет интерполяцию/экстраполяцию, а не предложенную авторами weighted KDE; exact conformal-validity не сохраняется. |
| [Vovk et al., COPA 2021](https://proceedings.mlr.press/v152/vovk21b.html) | Последовательное накопление evidence для обнаружения смены режима | CUSUM M5 не объявляется exchangeability martingale/e-process. Его нормировкам не доказано нужное свойство условного математического ожидания; Ville-bound и anytime false-alarm guarantee не заявляются. |
| [Bastani et al., NeurIPS 2022, Practical Adversarial Multivalid Conformal Prediction](https://arxiv.org/abs/2206.01067) | Контроль ошибок для множества групп в онлайне | У M5 ограниченный эмпирический ролевой guard и validation-порог. Это существенно слабее multivalidity при соответствующих предпосылках и обратной связи. |
| [Angelopoulos et al., ICLR 2024, Conformal Risk Control](https://research.google/pubs/conformal-risk-control/) | Калибровка параметра под допустимый риск | M5 применяет пользовательский bootstrap для осторожного выбора порога. Это не реализация теорем CRC; зависимость дней и адаптивный score требуют отдельного обоснования. |

## Обоснование конструкции

Полный PDF Facade доступен в [материалах USENIX](https://www.usenix.org/system/files/usenixsecurity26-kantchelian.pdf);
он также описывает многомасштабное обнаружение одиночных событий и дневной активности.
Поэтому сам принцип двух временных масштабов не заявляется новым. PDF CRD на сервере
авторского университета вернул 403; здесь его механизм характеризуется только по
доступной официальной аннотации. Полного формульного тождества с CRD это не исключает.

Прежние эксперименты показали: персональный хвост важен, но дискретность мешает
достичь заданной доли тревог; накопление помогает не на всех сценариях; рост Recall
может концентрировать FPR в ролях. Поэтому M5 разделяет четыре механизма:
статистическую надёжность личной опоры, её причинное обновление, накопление отклонения
с отдельным одиночным путём и эмпирический групповой защитный слой. Это проверяемая
инженерная гипотеза, а не доказанная новая теория.

Вес устойчивости снижается при изменении **прошлого** личного распределения, чтобы
не доверять короткой/меняющейся истории как устойчивой норме. Возможная неудача:
само начало атаки изменяет историю, вес личного контекста снижается и сигнал
маскируется ролью; обновление может поглотить длительную атаку. Эти риски проверяются
абляциями, а не устраняются утверждением о теоретической гарантии.

Ролевой guard ограничивает дисбаланс на validation, но при смене состава ролей или
дрейфе во времени не обещает фиксированный test-FPR. Главная проверка — фактический
FPR и Recall при заранее замороженном пороге, а не только top-1% ранжирование.
