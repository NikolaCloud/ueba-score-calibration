# M4v2: второй исследовательский раунд

Дата: 2026-11-02. Разрешённый пользователем объём — прототип на r4.2/r5.2.
Первый раунд не выполнил критерий улучшения. Его результаты и выбор EB30
сохраняются. До запуска второго раунда просмотрены только его selection-метрики;
файл аудита первого раунда уже создан, но его значения не использованы для
проектирования или выбора второго раунда. Все оценки остаются исследовательскими:
оба выпуска ранее изучались в исходной работе.

Данные, seeds, хронологические границы, общий IsolationForest и исходные M0–M4 —
как в protocol_m4_v2.md. Исходный test не используется. Отбор снова проводится
только на первой половине validation; окончательный аудит — на второй половине.
Повторное использование selection допускается для разработки и явно раскрывается.

## Механизмы

Для каждого замороженного calibration-профиля user/role/global сохраняется
эмпирическая хвостовая вероятность в наблюдавшихся точках. Между различными
наблюдениями вероятность линейно интерполируется. Выше максимума m:

`log p(s) = log p(m) - (s-m)/b`.

Это рабочая экспоненциальная экстраполяция, а не conformal p-value.
Исходная оценка b — среднее превышение над 75-м перцентилем. Для user она
сглаживается к медиане положительных пользовательских b данной роли с весом
`n/(n+30)`, для роли — к глобальной медиане с весом `n/(n+200)`.
Минимум b равен 0.1 глобальной медианы положительных b. Если положительных b
нет, используется стандартное отклонение всех calibration-score с минимумом 1e-6.
Профили (user,role) исключают перенос старого личного профиля при смене роли.

E30 и E5 объединяют log p геометрически по исходной иерархии с k_user=30 и 5
соответственно, k_role=200. EU использует только персональный хвост, при отсутствии
профиля — роль, затем global. Для всех вариантов отсутствующий профиль имеет вес 0.

T30/T5/TU — среднее соответствующего E30/E5/EU за последние 7 календарных дней
данного пользователя, включая текущий день. Используются только доступные на этот
момент scores, без меток и без будущих дней; при отсутствии активности день не
добавляется. История начинается с первого дня validation, поэтому selection
обеспечивает такой же прогрев аудита, как реальная эксплуатация. TG30 — такое же
накопление геометрического варианта G30 первого раунда. Сглаживание может задержать
обнаружение одиночных атак; это проверяется по сценариям.

## Отбор и аудит

Единственный дополнительный набор: E30, E5, EU, T30, T5, TU, TG30, в этом порядке.
Критерий прежний: Recall@1% не ниже лучшего M0–M4 на **каждом** выпуске и
проспективный max-role FPR не выше 1.1*M3. Среди прошедших — больший средний
Recall, затем меньший средний max-role FPR, затем порядок списка. Если ни один
не прошёл, основной прототип второго раунда — заранее назначенный E30, без
заявления о выполнении цели. Пороги 1% оцениваются на selection и замораживаются.

После записи selection_round2.json аудит выполняется для исходных M0–M4,
EB30/UZ первого раунда, выбранного кандидата второго раунда и EU/TU как проверок
вклада иерархии/накопления. Из этого аудита новый победитель не выбирается.
Нельзя приписывать иерархии улучшение, совпадающее с EU/TU.

Статистика аудита: 9999 парных bootstrap-выборок пользователей, усреднение пяти
seeds, 95% percentile CI. Семейство Holm включает сравнения выбранного варианта
второго раунда с M0–M4, EU и TU на обоих выпусках для Recall@1% и проспективного
max-role FPR; самосравнения исключаются. Центрированный bootstrap p-value
не обязан быть дуален percentile CI. Это условная исследовательская оценка,
не поправка, устраняющая адаптивную разработку на известных выпусках.

Неудачный второй раунд завершается отрицательным результатом, без следующих
поисковых раундов в этой задаче. Доказать превосходство по заказу невозможно;
разработка не должна менять метки, бюджеты, исходные формулы или условия сравнения.
