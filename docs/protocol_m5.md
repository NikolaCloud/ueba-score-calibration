# Предварительный протокол M5

Дата: 2026-11-02. Этот протокол фиксируется до расчёта результатов M5.
r4.2/r5.2 ранее изучены и используются только исследовательски. r6.2 до этой
работы не изучался; начата загрузка исходного архива. Данные r6.2 можно проверять
на целостность и поддержку меток до фиксации кода, но его test-scores и метрики
нельзя открывать до замораживания M5, baseline и процедуры порога.

## Метод и фиксированные параметры

M5 — адаптивная надстройка над теми же оценками IsolationForest. Индивидуальная
история (user,role) содержит последние 120 наблюдений. Вес наблюдения возраста a
календарных дней: w=2^(-a/60). Эффективный объём:
`n_eff=min(sum(w),sum(w)^2/sum(w²))`. Непрерывный эмпирический хвост интерполируется
между наблюдаемыми значениями, за максимумом — экспоненциальная экстраполяция,
как рабочая модель EU. Масштаб хвоста — среднее превышение над Q75, сглаженное
к типичному персональному масштабу роли с n_eff/(n_eff+30); floor=0.1 глобального.
Ролевая/общая опоры заморожены на calibration, личная история обновляется причинно.

Устойчивость определяется **до текущего наблюдения**: D — абсолютная разность
медиан последних 10 и предшествующих (до 40) наблюдений, делённая на максимум
1.4826*MAD всей истории и ролевого масштаба хвоста. При менее 20 наблюдениях D=0.
`wu=n_eff/(n_eff+30)/(1+D²)`, `wr=nr/(nr+200)`.
`L=-wu*log(pu)-(1-wu)*(wr*log(pr)+(1-wr)*log(pg))`.

Накопление: `C_t=max(0,exp(-delta_days/7)*C_prev+min(L,8)-2)`;
`Z_t=max(L,C_t)`. Два пути сохраняют сильное одиночное отклонение в исходном score,
но не гарантируют его обнаружение после калибровки конечного порога. C обнуляется
при смене роли. После оценки текущее сырое наблюдение winsorize-ограничивается
границами Q05-3*b и Q95+3*b **прошлого** личного профиля и добавляется в историю.
Порог и метки не участвуют в обновлении. Новая роль получает пустую личную историю.

Ролевой защитный слой: первая половина validation (guard) используется для оценки
95-го перцентиля Z среди отрицательных дней каждой роли; ролевой защитный сдвиг
`d_r=max(0,Q95_r-Q95_global)` при n_r>=100, иначе d_r=0. Итог `S=Z-d_r`.
Сдвиг заморожен после guard; он не корректируется по test. Неизвестная роль d=0.
Он ограничивает концентрацию ошибок на guard, но не даёт распределительно свободной
гарантии FPR на дрейфующем CERT. Все нарушения на test обязательно показываются.

Никакой подбор гиперпараметров M5 на test не допускается. Один основной вариант,
без поиска нескольких M5 и переименования победителя. Если он неудачен, результат отрицательный.

## Данные и поток

Внешние календарные доли прежние: train/calibration/validation/test=50/20/15/15%.
17 сопоставимых признаков из logon/device/file/email, HTTP не используется.
Детекторы: 200 деревьев, max_samples=min(2048,n_train), seeds 42–46, preprocessing
только train. Для r4.2/r5.2 используются прежние сырые scores; новые методы не
меняют детектор. Для r6.2 модель обучается аналогично после аудита исходных журналов.
Единица наблюдения — user-day; решение возможно после завершения дня, не в момент
отдельного события. Внутридневная задержка не оценивается.

Validation делится по календарю пополам: guard и threshold. Все методы получают
порог только на второй половине, чтобы сравнение использовало одинаковые даты.
Поток личного состояния начинается после calibration, без сброса между guard,
threshold и test. При оценке дня используется лишь более ранняя история данного
пользователя; role/global заморожены. Метки потока передаются только оценщику.

## Фиксированный набор сравнения

M0–M4, EU, TU, TM4, T30 — исходные формулы. EU/TU/T30 используют замороженные
calibration-профили; TU/TM4/T30 продолжают причинные 7-дневные окна через границу test.
AB — простой адаптивный baseline: тот же скользящий персональный хвост, без ролевого
объединения/устойчивости/CUSUM, score=max(текущая -log pu, среднее за 7 календарных дней).
При отсутствии user — role/global. Его защитный сдвиг d_r=0; общая процедура порога одинакова.

Абляции M5: без устойчивости (D=0); без роли (wr=0); без накопления (Z=L);
без одиночного пути (Z=C); без обновления личной истории (с затуханием веса);
без ролевого защитного слоя (d=0). Основной M5 по абляциям не переизбирается.

## Порог и ограничения

Для **всех** методов минимальный допустимый порог ищется на threshold-validation.
Сетка отрицательных квантилей: целевой FPR 0.0025, 0.005, 0.0075, 0.01.
Кандидаты дополнительно поднимаются до уровня, обеспечивающего эмпирический
max-role FPR<=5% на ролях с >=100 отрицательных дней threshold-validation.
Выбирается минимальный из кандидатов, у которого односторонняя 95%-я percentile
верхняя оценка FPR по 999 bootstrap-выборкам пользователей не выше 1%.
Если нет допустимого кандидата, порог +infinity и отсутствие тревог — честный результат.
Связки: тревога только при score>threshold. Порог не меняется по test.
Это эвристическая осторожная процедура, а не доказательство 95%-го покрытия после отбора.

Сильнейший существующий метод выбирается **по threshold-validation**, до test:
наибольший средний Recall среди M0–M4/EU/TU/TM4/T30/AB, затем меньший FPR,
затем порядок перечисления. Его имя фиксируется отдельно для каждого выпуска.
Абляции не участвуют. Дополнительно на test показываются все методы, без замены comparator.

## Показатели и критерий

Основной показатель: Recall при **фактическом** FPR<=1%. Если FPR>1% хотя бы в
одном seed, это явно отмечается; такой метод/выпуск не проходит основной критерий,
его Recall не выдаётся за результат при соблюдённом ограничении. Показываются
все seeds, среднее, худший seed и bootstrap CI FPR. Порог заново по test не ищется.
Для подтверждения ограничения дополнительно требуется верхняя 95% bootstrap-граница
FPR M5 не выше 1%; это условная оценка для пользовательской популяции данного выпуска.

Успех на независимом выпуске требует одновременно: все пять test FPR<=1%; прирост
среднего Recall против заранее выбранного comparator >=0.05; нижняя 95% граница
парной bootstrap-разности Recall >0.05; значимость после Holm. Отдельно показывается,
сохранился ли ролевой предел 5% (n>=100), и максимум по **всем** ролям, включая малые.
Простое отсутствие значимости разности FPR не означает соблюдение его ограничения.

Дополнительно: Precision, Recall@1% с общим ретроспективным списком,
max-role FPR/all и n>=100, доли тревог, scenario recall, задержка обнаружения,
результат по n_eff истории (0–9,10–29,30–59,>=60), распределение весов/нестабильности.
Сценарии с <20 положительных дней/<5 аккаунтов считаются слабо поддержанными.
Задержка в календарных днях от первого официально отмеченного user-day инцидента до
первой тревоги на отмеченном дне. Начавшиеся до test инциденты отдельно как left-censored.
Необнаруженные не исключаются: детектируемая доля и штраф min(delay,7) с 7 для
необнаруженных при наличии 7 календарных дней наблюдения. Точность меток/связей инцидентов
проверяется; если доступны только аккаунт-сценарий, это явно обозначается и не называется инцидентом.

9999 парных bootstrap-выборок пользователей, среднее по пяти seeds внутри каждой.
Пороги/профили/имя comparator не переобучаются внутри bootstrap. Одни multiplicities
для всех сравниваемых методов; top-1% заново рассчитывается для размера bootstrap-когорты.
95% percentile CI и центрированный двусторонний bootstrap p-value (не дуальные CI).
Основная семья Holm: M5 против зафиксированного comparator, Recall и FPR, все доступные
выпуски. Отдельная исследовательская семья: все методы/абляции против M5 для Recall,
FPR и max-role FPR. r6.2 — единственный подтверждающий выпуск, если он подготовлен и
его код/правила заморожены до первого test-score. Межрелизный успех не заявляется
только по улучшению одного выпуска или одной метрики.

## Завершение

Сохраняются формулы, источники аналогов, code/config SHA256 до test, решения выбора
comparator, пороги/их validation-проверки, численные результаты всех seeds, абляции,
bootstrap, графики PNG/SVG, научный отчёт на русском и ZIP без больших исходных данных.
Независимая проверка может опровергнуть гипотезу; её результат не используется для
ещё одного раунда настройки в этой задаче. Отказ загрузки/несопоставимость/недостаток
атак документируются, а незапущенные эксперименты не выдаются за выполненные.
