# Разработка M4v2: исследовательский протокол

Дата: 2026-11-02. Результаты r4.2 и r5.2 уже открыты. Этот документ не делает
их повторное использование независимой подтверждающей проверкой.

## Цель

Разработать отдельную версию калибровки, устраняющую два ограничения исходного M4:
дискретность персональных хвостов и подавление персонального сигнала арифметической
смесью с обычной для роли активностью. Исходные M0–M4 и их результаты не изменяются.
Гарантии выигрыша, conformal-validity или математической новизны не предполагаются.

## Допустимые данные

Разработка использует только calibration и validation основных протоколов r4.2/r5.2,
сохранённые scores одних и тех же IsolationForest для seeds 42–46. Ранее изученные test
не используются для выбора параметров новой версии и повторной оценки её качества.
Даже validation этих выпусков нельзя считать полностью новым holdout: часть дат
входила в ранее открытые дополнительные периоды. Выводы называются исследовательскими.

Validation каждого выпуска делится пополам по календарным датам. Первая половина —
выбор варианта и проспективного порога; вторая — однократный аудит разработки.
В аудит идут выбранный вариант, M0–M4 и непрерывная персональная абляция;
другие кандидаты на аудите не ранжируются для повторного выбора победителя.

## Фиксированный набор кандидатов одного раунда

1. G30: прежние веса 30/200, геометрическое объединение вероятностей
   (взвешенная сумма -log(p)), вместо среднего самих вероятностей.
2. Z30: непрерывная нормировка исходного score относительно иерархических робастных
   центра и масштаба; веса центра по n/(n+k), k_user=30,k_role=200.
3. EB30: центр user/role/global с эмпирически оценённой межпрофильной дисперсией
   и reliability весом tau²/(tau²+noise²/n); робастная дисперсия user сглаживается
   к внутригрупповой дисперсии роли при k_scale=30.
4. EB90: то же, k_scale=90; это заранее заданная проверка регуляризации масштаба.
5. UZ: персональная непрерывная нормировка, без shrinkage центра. Это сильная
   абляция: при её равенстве новой схеме пользу иерархии утверждать нельзя.

Центр — медиана; масштаб — 1.4826*MAD, с защитой постоянных профилей. Для робастной
оценки noise медианы применяется рабочее приближение (pi/2)*scale²/n.
Ролевой масштаб отражает типичную внутрипользовательскую вариативность, а не
разброс средних разных сотрудников. Минимальный масштаб = 0.1*глобальный
внутрипользовательский масштаб. История user относится к паре (user,role), чтобы
не переносить профиль старой роли на новую. При отсутствии user-профиля используется
роль с предиктивной дисперсией, включающей межпользовательскую неоднородность;
при отсутствии роли — глобальный fallback. Оцениваемые дни не пополняют профили.

Для Z/EB/UZ итоговый score — непрерывное одностороннее стандартизованное отклонение;
оно не объявляется p-value. Чем больше score, тем сильнее отклонение вверх.
Общий детектор не переобучается при сравнении калибровок, признаки не изменяются.

## Правило выбора до аудита

Основной кандидат по умолчанию — EB30. Формально квалифицирован кандидат, который
на первой половине validation обоих выпусков достигает Recall@1% не ниже лучшего
из M0–M4 и max-role FPR не выше 1.1*соответствующего M3 при пороге 1% тревог.
Среди квалифицированных выбирается наибольший средний Recall@1% двух выпусков;
при равенстве — меньшее среднее max-role FPR, затем порядок списка выше.
UZ в выборе участвует: если выигрывает простая персональная схема, это фиксируется
как результат разработки и не переименовывается в доказательство пользы иерархии.
Если квалифицированных нет, оценивается заранее назначенный EB30, со статусом
«критерий улучшения разработки не выполнен»; правило после просмотра аудита не меняется.

## Оценка

Сохраняются Recall/Precision@1%, max-role FPR и FPR при проспективном пороге,
фактические доли тревог, метрики по сценариям, размер поддержки и все пять seeds.
Дополнительно max-role FPR в ретроспективном top-1%, чтобы отделять перераспределение
ошибок от недостижения проспективного бюджета дискретными методами.
95% CI: парный bootstrap по пользователям на второй половине validation,
среднее по seeds; сравнения выбранной версии с M0–M4, поправка Holm.
Эти интервалы описывают аудит разработки, не устраняют адаптивность к уже известным
выпускам. Для подтверждения заметного выигрыша нужен новый закрытый выпуск/датасет
после фиксации выбранного алгоритма. Возможный кандидат — ещё не изученный CERT r6.2.

## Источники идеи и ограничения

Дискретность локальных хвостов обсуждается в
[Hennhöfer & Preisach, 2026](https://arxiv.org/abs/2603.23205).
Иерархический shrinkage по объёму группы уже описан в
[HCC-CP, JSM 2026](https://ww2.amstat.org/meetings/jsm/2026/onlineprogram/abstract.cfm?sid=8751&tid=9087).
Нормировка с partial pooling — рабочая модель; её параметры и нормальные
приближения не дают автоматической гарантии FPR на нестационарных данных CERT.
